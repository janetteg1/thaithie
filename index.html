02 — Lab Submissions

Five Labs, One Journey

01
UI Fundamentals
Jetpack Compose

Building static UI screens using Compose fundamentals — Column, Row, Box, Text, Image, and basic theming.

▶ YouTube
Lab 1 taught me the declarative mindset of Compose. Coming from XML layouts, thinking in composable functions felt unnatural at first, but building the first screen from scratch made it click. The biggest challenge was understanding recomposition.
02
Interaction & State
State Management

Adding interactivity with buttons, text fields, and state hoisting. Understanding remember and mutableStateOf.

▶ YouTube
Understanding state hoisting changed how I think about data flow. Moving state up to the parent composable felt counterintuitive but made my components far more reusable and testable.
03
Material Design 3
Theming

Applying Material 3 components, dynamic colour theming, typography scale, and elevation system.

▶ YouTube
Material 3's colour token system was initially overwhelming but I appreciated how it forced consistency across the entire app. Setting up the custom green theme for EcoLoop gave the app a real identity.
04
Navigation Compose
Multi-Screen

Implementing type-safe navigation with NavHost, sealed class routes, and argument passing between screens.

▶ YouTube
Sealed class routes eliminated the string typo bugs I had in earlier attempts. Building the 8-screen EcoLoop navigation flow in a single NavHost made the whole app structure feel clean and maintainable.
05
Room Database
Local Persistence

Persisting data locally with Room — defining entities, DAOs, and the database class with Kotlin coroutines.

▶ YouTube
Room's annotation-driven approach made database setup far less error-prone than raw SQLite. Using Flow return types in DAOs so that the UI updates automatically was the most satisfying moment of the lab series.

03 — Project Submissions

Building EcoLoop

Project 1 Lab 4 + Features Navigation

EcoLoop — Foundation

Multi-screen navigation with 8 screens, static data, and core UI components

P1

Problem Statement

UKM students lack a trusted, campus-specific platform to coordinate shared rides and exchange pre-loved items, leading to unnecessary fuel consumption and resource waste on campus.

Working Features

  • 8-screen navigation with sealed class routes
  • Splash, Home, Carpool, Marketplace screens
  • Post Listing, Ride Detail, Item Detail, Profile
  • Static carpool and marketplace listings
  • Bottom navigation bar
▶ Video Showcase ⌥ GitHub Repo

Lessons Learned

Project 1 taught me to think about navigation architecture before writing any UI code. Designing all 8 routes upfront as a sealed class prevented back-stack bugs later. I also learned how important placeholder data is for testing UI without a backend.

Project 2 Room Firebase API Camera

EcoLoop — Full Stack

Local persistence · Cloud sync · Live AQI data · Camera sensor integration

P2

Problem Statement

EcoLoop addresses two sustainability challenges simultaneously: high per-capita fuel use from single-occupancy commutes and growing campus waste from students discarding still-usable items. By building a circular economy platform on campus, EcoLoop directly supports SDG 12.

Technical Pillars

  • Room DB — UserProfile, SavedRides, Wishlist entities
  • Firebase Firestore — rides/ and listings/ collections, real-time sync
  • Open-Meteo API — live AQI banner on Home screen
  • CameraX — photo capture for marketplace listings
▶ Video Showcase ⌥ GitHub Repo

Lessons Learned

Integrating four technical pillars simultaneously forced me to think about data flow holistically. The hardest part was making Room and Firestore stay in sync without duplicating state. I also learned that Gradle dependency management is non-trivial — the Firebase BOM was the key to resolving version conflicts cleanly.

04 — Reflection & Learning Journey

From Lab 1 to Project 2

Lab 1

First Composable

Wrote my first @Composable function and understood why the declarative model is fundamentally different from XML views. Struggled with previews but got the basics working.

Lab 2

State & Interactivity

Grasped state hoisting and the single source of truth principle. Built my first interactive form with validation — a foundation that would prove essential in PostListingScreen.

Lab 3

Design System Thinking

Material 3 introduced me to design tokens and theming at scale. Creating EcoLoop's green colour scheme taught me that brand identity in an app starts at the theme layer.

Lab 4 → Project 1

Navigation Architecture

Type-safe navigation with sealed class routes was the turning point. Project 1 brought all prior labs together into a coherent 8-screen product for the first time.

Lab 5 → Project 2

Full-Stack Integration

Room, Firebase, Retrofit, and CameraX in one project was the biggest challenge of the course. Debugging Gradle dependency errors, Firestore security rules, and timezone issues in the AQI API all in the same week was intense but rewarding.

SDG Impact

Technology for Sustainability

Building EcoLoop made SDG 12 tangible for me. Every carpool ride coordinated through the app represents real CO₂ avoided. Every pre-loved item sold extends its lifecycle by months or years. Small individual choices, scaled across a campus of thousands, create measurable environmental impact.
